# 已使用独立工作树时交付并保留工作分支

**状态：已废止。**由 [ADR-0015](0015-remove-worktree-from-git-delivery.md) 取代；修改仓库文件后的收尾以 [ADR-0014](0014-git-delivery-after-changes.md) 与 ADR-0015 为准。

部分取代 [ADR-0005](0005-remove-worktree-rules.md)。普通仓库任务仍不默认创建工作树；当对话已经在独立工作树中实施文件变更时，每轮任务完成后先推送工作分支，再合并并推送其已确定的源分支。保留工作树和远程工作分支，供同一对话下一轮文件变更复用；合并后的源检出目录停留在源分支。

这让每轮工作既有可追溯的远程工作分支，也交付到原来的分支。宿主可能继续把会话固定在工作树目录，因此规则分别核对 Git 分支状态与会话目录状态，避免把两者混为一谈。源分支身份不明、合并冲突、仓库要求 PR 或推送被拒时，停止自动合并并保留现场。

## Considered Options

- **每轮合并后删除工作树**：会话后续文件变更无法复用同一工作分支，且宿主可能仍指向被删除的目录。
- **仅推送工作分支**：源分支没有获得已完成的工作，用户还需另行合并。

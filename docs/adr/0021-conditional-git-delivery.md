# 将 Git 收尾改为收尾时评估的低优先级默认约定

> 状态：已由 [ADR-0023](0023-remove-git-delivery.md) 取代。

修订 [ADR-0014](0014-git-delivery-after-changes.md) 与 [ADR-0015](0015-remove-worktree-from-git-delivery.md)。

2026-11-22 决定保留 `Git 收尾`（`plugins/letsgo/skills/letsgo/references/git-delivery.md`），但将其从无条件自动执行降级为低优先级的默认收尾约定，并移除“另建分支自动合并回原分支并推送原分支”的规则：

- **优先级让位**：当用户本轮指令、项目级规则（如 `AGENTS.md`、发布脚本）或当前使用的技能与多智能体工具（如 `/implement`、`/implement-spec`、`/prototype`、`/swarm`、PR 流程）对分支、提交或推送另有约定时，服从后者。
- **收尾时机由智能体现场评估抉择**：仅在整个会话目标已达成并通过验证时才评估采用；多轮访谈或探索中途的文件更新、未完结的分步任务及子代理局部工作不执行 Git 收尾。
- **只操作当前分支**：默认收尾只针对当前工作分支提交并推送；处于临时分支或独立检出目录且去向不明时，由智能体结合创建目的判断或停下报告询问，不再自动合并回原分支。

无条件执行与跨分支自动回并会破坏 `mattpocock-skills`（只本地提交、集成分支合并、保留 `prototype/*` 分支）、`/swarm`（仅在用户要求时推送）、多轮访谈内联更新文档以及本仓库自身的 `scripts/release.sh` 发布流程；而彻底删除该规则又会让日常简单改动退回每次需人工嘱咐提交推送。

## Considered Options

- **彻底删除 `git-delivery.md`**：完全无冲突，但三端宿主默认均不主动提交与推送，日常独立小任务每次都需人工重复要求。
- **维持原规则不变**：继续与第三方技能、多智能体编排、原型分支及发布脚本冲突，且在独立工作树中回并已被主目录检出的原分支会直接失败。

## Consequences

- `GLOSSARY.md` 中“Git 收尾”的定义更新为不冲突前提下对当前分支评估执行的默认提交与推送。
- `stepping` 与 `matt-flow` 对 `Git 收尾` 的引用同步去掉“合并”表述，限定在任务或路线终局收尾且无其他分支/PR 约定时评估执行。

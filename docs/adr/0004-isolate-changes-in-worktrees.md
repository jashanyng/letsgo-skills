# 改动前一律隔离工作树，交付后合并、推送并清理

**状态：已废止。**由 [ADR-0005](0005-remove-worktree-rules.md) 与 [ADR-0015](0015-remove-worktree-from-git-delivery.md) 取代。以下内容仅记录当时的决定，不再作为现行规则。

全局规则要求：任务修改 git 仓库内的文件时，默认在**隔离工作树**中实施；完成后合并到交付分支并推送，经四项安全检查后删除工作树与本次创建的工作分支。

此前改动直接落在源分支，或由宿主临时建出的工作树里；交付后工作树与分支常被遗忘，会话也可能绑定到已被合并、删除的目录。统一隔离与清理后，源分支不会被半成品污染，会话的工作目录始终有效，合并与清理的责任落在同一条规则上。

## Considered Options

- **仅在 `main`/`dev` 上要求隔离**：规则更轻，但在其他分支上直接改动时同样会留下无人收尾的状态，且要多一层“当前分支是什么”的判断。
- **完成后保留工作树，由用户手动清理**：最安全，但已合并的目录和分支会不断堆积，用户要反复手工核对。
- **每次由智能体视情况决定**：灵活，但结果因对话而异，无法形成可依赖的约定。

## Consequences

- 每次改动多一次建与删的成本，换取不污染源分支；小改动可由用户明确要求原地改动来免除。
- 清理只允许删除本次记录、以 `claude/` 或 `codex/` 开头的工作分支，并要求已合并进远程交付分支，源分支与 `main`、`master`、`dev`、`develop` 永不删除。
- 同一对话在清理后继续改动时，需要重新创建隔离工作树。
- 推送触发 CI 时不等待结果，CI 失败要在之后另行处理。

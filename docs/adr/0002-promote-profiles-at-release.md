# 默认画像在发布时由本机快照提升，且每次发布前必须重新快照

> 已被 [ADR-0003](0003-no-bundled-host-snapshots.md) 取代：插件不再内置任何主机快照，发布也不再要求快照。

此前 `letsgo:snap-environment` 每次确认快照后，都会把它顺手复制到开发副本里的默认画像位置。这让一个运行时技能依赖“本机恰好有开发副本”这一作者专属的前提。现在快照只写本机快照；`scripts/release.sh` 在发布时把比默认画像新的本机快照复制进仓库，并且只要有任何资产的默认画像早于上一次发布，就拒绝发布。

## Considered Options

- **快照时同步到开发副本（原做法）**：默认画像随时最新，但运行时技能依赖作者的检出路径，而且发布时仍可能带上很久没更新的画像。
- **发布时只提醒、不阻断**：发布不需要连接主机，但默认画像会悄悄过期，违背“每个版本都带最新默认画像”的目标。

## Consequences

- 每次发布前都要为全部资产运行一次 `snap-environment`，即使这次发布与环境无关。
- 连不上的主机不能跳过：仍要快照，未采集到的旧事实保留并标为未验证；作者确认其无变化时，以 `declared` 记录当天的 `declared_at`。
- 门禁按 UTC 日期比较，同一天内早于上一个标签的快照也会被视为已更新。

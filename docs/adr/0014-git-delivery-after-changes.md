# 修改仓库文件后由智能体完成 Git 收尾

> 状态：独立工作树相关规定已由 [ADR-0015](0015-remove-worktree-from-git-delivery.md) 移除；无条件执行与非初始分支回并规则已由 [ADR-0021](0021-conditional-git-delivery.md) 修订为低优先级默认约定并仅针对当前分支评估执行。

部分取代 [ADR-0005](0005-remove-worktree-rules.md) 与 [ADR-0006](0006-conditional-worktree-delivery.md)。2026-11-11 决定：任务修改了 git 仓库中的文件时，每轮完成并通过选定的验收后，由智能体直接完成 Git 收尾，Codex 与 Claude Code 相同。在初始分支上工作时提交并推送；在独立工作树或智能体自建的分支上工作时，推送工作分支后合并回原分支并推送原分支，工作树与工作分支保留。规范来源是插件内的 `_rules/spec/references/git-delivery.md`。普通仓库任务仍不默认创建工作树。

Claude Code 默认只在用户要求时提交，并常把会话放进独立工作树；工作完成后改动停在工作分支或本地，用户需要另行合并与推送。把收尾写成用户的长期指示后，每轮工作都会落到原分支并保存到远程。

## Considered Options

- **只为 Claude Code 制定**：贴合当前痛点，但两端读取同一份规则，分别规定会使行为分叉。
- **每次提交前征求同意**：最保守，但正是需要消除的重复确认。
- **只推送工作分支，不合并**：原分支得不到成果，仍需用户手工合并。

## Consequences

- 只在六种情形停下：原分支无法确定、合并冲突、仓库要求 PR 或分支受保护、本轮改动与既有改动无法区分、差异可能含秘密、推送被拒。仓库没有远程时只做本地提交。
- 普通对话依靠 `conventions` 命中“修改 git 仓库文件”场景，命中不能保证。
- 推送一旦完成即离开本地；提交范围审查与秘密检查是自动推送前唯一的保护。

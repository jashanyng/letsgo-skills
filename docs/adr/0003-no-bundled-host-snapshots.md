# 不内置主机快照：按需读取本机快照，缺失即停止

> 快照机制已由 [ADR-0008](0008-plugin-runtime-and-personal-context.md) 取代；本文件仅记录历史决策。

取代 [ADR-0002](0002-promote-profiles-at-release.md)，以及 [ADR-0001](0001-publish-as-plugin.md) 中“采集得到的画像在下次发布后成为所有机器的默认画像”这一条后果。

此前插件随版本发布每个资产的默认画像，并要求发布前为全部资产重新快照。这让发布依赖作者能连上所有主机，也让插件携带了主机的内网地址、服务与端口细节。现在插件不再内置任何主机快照：主机事实只来自用户本机的 `~/.agents/generated/product/prop/profiles/<资产>.md`，由 `letsgo:snap-environment` 生成；需要某台主机的快照而它不存在时，技能停止并请用户采集。发布与安装都与快照无关。

私人资产因此分为两类。域名、网络拓扑这类由用户声明、各机器都相同的事实是**个人信息资产**，仍随插件发布；可以采集的 7 台主机是**主机环境资产**，只存在于本机快照。

## Considered Options

- **保留默认画像、发布前强制快照（ADR-0002）**：新机器装上即有资料可读，但每次发布都要连上全部主机，且插件内置主机细节。
- **首次运行时强制全量快照，用标志位只触发一次**：保证每台机器都有快照，但宿主不通知卸载、Codex 不区分重装与更新，标志位无法可靠实现“重装重做、更新不做”；而且会拦住与快照无关的技能。

## Consequences

- 新机器第一次用到某台主机时，需要先为它采集快照；只缺条件依赖的快照时任务继续，并提示补采。
- 主机快照不再随版本同步到其他机器，每台机器各自采集。
- 个人信息资产的修改仍需提交并发布。

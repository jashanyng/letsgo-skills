# 新增显式技能 git-wrap

维持 [ADR-0023](0023-remove-git-delivery.md)“插件不内置隐式默认 Git 收尾规则”的结论，同时修订 [ADR-0015](0015-remove-worktree-from-git-delivery.md) 中“插件包不出现工作树”的限制，并与 [ADR-0024](0024-matt-guide-skill.md) 一并修订 [ADR-0017](0017-minimal-plugin.md) 与 [ADR-0022](0022-swarm-up-skill.md) 中关于插件技能数量的部分（插件技能由 7 个增至 9 个，发布为 3.5.0）。

2026-11-22 决定新增显式技能 `git-wrap`（`name: "letsgo:git-wrap"`，菜单显示 `letsgo: git wrap`），专门在全部开发任务结束后由用户显式触发，完成跨仓库、链接工作树（linked worktree）与任务临时分支的安全收尾。

- **动机**：[ADR-0023](0023-remove-git-delivery.md) 移除隐式 `Git 收尾` 规则，消除了日常对话、多轮访谈、`/swarm`、`/prototype` 与发布脚本中的自动提交／推送干扰；但用户在多仓库协作、宿主自建的链接工作树或任务临时分支完成全套开发后，仍需要一个可控的终局“一键安全收尾”能力。将其收口为仅显式调用的 `git-wrap`，彻底解耦“日常无隐式 Git 干扰”与“终局跨仓安全收尾”之间的矛盾。
- **只允许显式调用**：`disable-model-invocation: true`、`allow_implicit_invocation: false`。日常对话仍没有任何隐式默认 Git 提交、合并或推送规则。
- **多仓库范围识别**：有前序任务上下文时纳入本次会话修改过、创建过工作树或用户点名的所有 Git 仓库（含子仓库与链接工作树），只暂存并提交本次任务相关改动，保留任务前无关改动与暂存状态（混杂且无法安全剥离时停下询问）；空白会话直接调用时纳入指定路径或当前仓库，若当前为多仓库父目录则扫描其下存在未提交改动、未推送提交或关联工作树的子仓库。干净且无待收尾项的仓库直接记为“无需操作”。
- **安全检查与英文提交**：逐仓检查状态与差异，疑似包含秘密（密码、令牌、私钥）或不应入库的大型构建产物／临时文件时停止该仓并报告；有待提交改动时，紧扣任务目标与实际改动撰写简洁准确的英文提交信息（沿用仓库既有英文前缀或 Conventional Commits 惯例，标题与正文均为英文）。
- **长期分支刚性保护与三层源分支推断**：`main`、`master`、`dev`、`develop`、`trunk`、`staging`、`production` 及 `release/*` 永远视为源分支本身，只原地提交与推送，严禁向其他分支合并或删除。仅当处于链接工作树或有明确证据属于单任务临时分支（如本会话新建、`claude/*`、`codex/*`、`worktree-*` 等且分叉源可考）时才执行回并；对 `prototype/*` 原型分支或身份不明的分支停下请用户确认。用户未指定源分支时依次按三层推断：① 本会话起点或 `git reflog` 分支创建记录；② 链接工作树对应主检出目录（由 `git worktree list --porcelain` 定位）当前检出的长期分支并经 `git merge-base` 核验分叉拓扑；③ 分叉拓扑最近的长期分支（等距时优先 `dev`/`develop`，其次 `main`/`master`）。存在无法可靠区分的歧义时立即停下请用户指定，绝不盲猜。
- **通过主检出目录跨工作树合并推送与停止保护**：源分支已在主检出目录检出时，先核验主检出目录无阻碍合并的脏改动，再通过主检出目录（`git -C <主检出目录>`）合并任务分支并推送源分支；未在其他工作树检出时则在主检出目录或当前目录切换至源分支合并推送。遇到合并冲突（先中止未完成合并以保留现场）、远程分支受保护要求 PR 或推送被拒时停下报告，严禁 `--force` 强制推送；推送触发 CI 时不等待轮询。
- **四项安全门槛下的清理评估**：仅当同时满足四项门槛——① 任务提交已完整合入源分支且源分支已推送到远程（无远程时以本地合并完成为准）；② 待删工作树内无未提交变更或未跟踪残留文件；③ 待删分支不在长期保护名单、非 `prototype/*` 且无未关闭关联 PR；④ 当前工作目录若位于待删工作树内已先切回主检出目录——才判定为“推荐删除”并移除链接工作树及已合并的本地／本轮已推同名远程临时分支；任一不满足即保留并说明原因，最后逐仓输出汇总报告。

## Considered Options

- **重新启用隐式 `git-delivery.md` 并加上工作树逻辑**：仍会在日常访谈、多智能体局部工作、原型分支与发布脚本中频繁冲突或误触发。
- **允许 `git-wrap` 在源分支存疑时自动选 `main` 或强制清理工作树**：一旦项目实际源分支为 `dev` 或工作树内有未跟踪产物，会造成错并分支或不可逆的数据丢失。
- **只支持单仓库、原地提交推送而不处理工作树回并**：无法解决多仓库工程与链接工作树结束后改动滞留临时分支的痛点。

## Consequences

- 维持 [ADR-0023](0023-remove-git-delivery.md)“不设隐式默认 Git 收尾规则”的结论；修订 [ADR-0015](0015-remove-worktree-from-git-delivery.md) 中“插件包不出现工作树”的限制，允许在显式技能 `git-wrap` 中处理链接工作树与源分支回并评估。
- 与 [ADR-0024](0024-matt-guide-skill.md) 一并使插件技能由 7 个增至 9 个，发布为 3.5.0（向后兼容新增功能）。
- `scripts/validate.py` 的 `EXPECTED_SKILLS` 加入 `git-wrap`，同步更新三端 `plugin.json`、`GLOSSARY.md`（新增 `Git 收尾` 与 `源分支` 术语）、`docs/authoring.md`、`AGENTS.md` 与 `README.md`。

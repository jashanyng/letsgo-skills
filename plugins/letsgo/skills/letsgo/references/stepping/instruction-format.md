# 步骤输出格式

主答复首行写[进度标识](workflow.md#进度标识)，随后给出目标、具体操作、完成证据和停止条件。

- **命令步骤**：给出从准确入口开始、可直接执行的完整命令和必要路径；不写“检查配置”“查看状态”之类的概述。多条命令按[命令集](../output.md#命令集)书写。
- **界面步骤**：给出入口、逐项点击或选择路径、需填写的精确内容和完成后可观察的结果；不用“按提示操作”代替。
- 执行细节取决于尚未核实的状态时，在步骤里给出发现方式和分支停止条件，不猜测具体值。
- 同一目标只展示一种主方式；文件新增或修改另附可选命令集，见下文。

## 新增与修改文件

- 新增文件：给出准确路径和完整内容。
- 修改文件：给出准确路径、定位上下文，以及受影响区域“修改前”和“修改后”的完整代码块，足以无歧义替换；不重复未改动的大段内容。
- 代码、配置或脚本只加解释非显而易见意图、约束或安全边界的注释，保留有效的既有注释。

## 文件写入命令集

步骤含文件新增或修改且有安全的命令实现时，把文件写入、后续操作与验证合进同一组命令集；没有其他命令时也给一组**可选命令集**。上方展示的完整文件或“修改前／修改后”片段仍保留供审阅。命令集必须先检查文件状态，再决定动作：

- 文件已由用户手动正确完成：跳过写入和备份，只在授权范围内补做必要的校验、重载和行为验证；整步已完成时只验证。不同写法只有能用可靠的行为检查证明等效时才算已完成。
- 文件仍是本步核实过的旧状态：生成候选并校验，写入前再次确认旧状态未变，备份原件后在同一文件系统原子替换；替换后验证失败则恢复备份。
- 文件是其他内容、只完成一部分或无法判定：停止并显示实际差异，不覆盖用户改动。
- 新文件只在不存在时创建；已存在且正确时只验证，冲突时停止。

移动、重命名或删除文件同样先检查现场、冲突即停；删除另需授权与备份。命令集再次执行必须安全，不重复产生副作用；完成条件覆盖文件结构、权限及适用的服务或行为结果。输出前自检：文件变更是否已纳入命令集，命令集能否核验用户可能已手动完成的结果。

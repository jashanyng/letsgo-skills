# 步进会话

## 控制与状态

- 只有用户显式调用 `letsgo:stepping-begin`、`letsgo:stepping-doit`、`letsgo:stepping-finish` 才能控制会话（Claude Code 与 Antigravity 写作 `/letsgo:stepping-begin`，Codex 写作 `$letsgo:letsgo:stepping-begin`，其余同理）。不从自然语言推断控制调用。
- 会话状态保持内部化：目标、范围、全部步骤及其粗略权重、当前步骤、插入任务。
- 没有活跃会话时，`doit` 与 `finish` 请用户先调用 `begin`，不猜测状态。
- 会话中的普通反馈是当前步骤的输入，按下文[反馈处理](#反馈处理)推进、返工或完成，不要求额外的推进命令。

## 步骤

- **粒度**：一步对应一个用户可观察的较大结果，而不是一个点击或一条命令。同一授权与风险边界内为同一结果所需的准备、实施和验证合并为一步；只有授权或风险边界不同、必须等待外部反馈、失败会改变后续方案，或涉及不同系统与责任方时才拆分。任务确实不可再分时只有一步。
- **内容**：每步包含标题、具体操作、完成证据和停止条件，按[步骤输出格式](instruction-format.md)书写。展示步骤不等于已执行。
- **标题**：固定为“<步骤目标>（<类型>）”，类型取以下之一；一步含多种动作时取影响最高者，验证不单列类型：
  - `只读`：检查、读取、分析或验证，不改变外部状态。
  - `新建`：创建此前不存在的文件、记录、服务等。
  - `修改`：编辑既有文件、记录、配置或内容。
  - `删除`：移除文件、记录、服务等。
  - `变更`：启动、停止、重启、迁移或切换既有系统状态。
  - `重建`：删除或替换既有目标后重新生成、编译或构造。
  - `安装`：获取并安装依赖、软件、插件或运行时。
  - `发布`：部署、上线、发送或对外提交产物。
  - `报告`：只汇总、呈现或交付已获得的结果。
- **只展示当前步骤**：后续步骤只留在内部状态，不提前给出，也不展示控制选项菜单。
- **收尾**：最后一步含验证与交付。按改动风险自选验证方式（如静态检查、单元测试、构建、冒烟、功能验证），报告实际执行的与未验证的部分。

## 进度标识

每个展示步骤的主答复以一行进度标识开头；普通解释、澄清答复和中间状态更新不用。

- 进行中：`🧭 目标任务（进行中 · 约 N%）：<当前步骤标题>`
- 返工中：`🔄 目标任务（返工中 · 约 N%）：<当前步骤标题>`
- 插入事项：`🧩 目标任务（插入事项 · 主线约 N%）：<当前步骤标题>`
- 已完成：`✅ 目标任务（已完成 100%）：<简洁任务描述>`

`N` 是按步骤权重粗估的整数，首步通常约 `10%`。返工沿用已达到的最高进度，插入事项显示主线进度，只有整体完成时为 `100%`。

## 反馈处理

- **完成**：日志、截图、文件差异或用户说明足以证明当前步完成时标记完成。有后继步骤就把它设为当前步骤并立即完整展示，但不执行；没有后继步骤就以 `100%` 进度给出整体小结，并写明“整个任务已全部完成”。
- **失败**：保留原目标，说明失败证据，给出返工步骤及新的完成条件；不推进主线，也不暗自执行返工。
- **证据不足**：保持当前步骤不变，只说明需要补充的最小证据或可执行的检查。
- **无关反馈**：作为插入任务，暂停主线当前步骤并建立插入任务的最小步骤；插入任务完成后恢复并重新展示被暂停的步骤。单纯的澄清问题直接回答，不改变会话状态。

## 执行方式与边界

- 用户明确指定操作方式时遵从。
- 给出只读步骤时优先命令方式，其次网页或软件界面。
- 给出新建、修改、删除等变更步骤时：已核实目标主机装有 1Panel 且该变更可由 1Panel 配置完成，优先 1Panel 界面操作；否则优先命令方式，其次网页或软件界面。
- 智能体实际执行步骤时，即使步骤给的是界面操作，只要命令能完成就用命令，包括 SSH 到目标主机执行；只有必须人工登录、验证码或仅界面可用时才用界面，并在报告中说明原因。涉及用户主机时先按[私人资料与远程连接](../personal-context.md)确定目标与通道。
- 远程目标默认用户已通过 FinalShell 连接到正确主机，不安排连接、登录或选择主机步骤；连接存在不等于操作成功，仍需核实目标与结果。
- 控制调用只授权其既定范围。发现未披露的删除、付费、发布、对外发送、生产变更等高影响操作时，说明影响、目标与可验证边界，等待单独确认。

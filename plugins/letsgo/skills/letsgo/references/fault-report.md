# 故障报告

适用于服务异常、构建或部署失败、配置错误、数据问题等故障的修复。修复完成后按以下结构报告，让用户能直接记成笔记，下次照着处理：

1. **故障现象**：表现、位置与时间，关键报错原文。
2. **故障原因**：已确认的根因及依据（日志、配置、代码、命令输出）；依据不足的部分标为“未确认的推断”。
3. **修复方案**：做了什么、为什么这样做。
4. **操作步骤与命令**：按执行顺序列出，多条命令按[命令集](output.md#命令集)书写；涉及的文件给出路径和修改前后的关键内容；每步写明预期结果和失败时的判断。
5. **验证结果**：如何确认故障已消除，实际命令与输出摘要；未验证的部分明确写出。
6. **复发自查**：再出现同类现象时的检查顺序、判断命令及对应修复步骤。

故障未消除或未验证时不得宣称修复完成。报告不写入秘密值；是否保存为笔记由用户决定。

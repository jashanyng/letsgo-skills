# matt 路线与门禁规范

适用于 `letsgo:matt-flow` 的技能读取、路线图规划与门禁输出规范。

## 读取技能

1. 先读取宿主技能目录中的 `ask-matt/SKILL.md`（通常位于 `~/.agents/skills/ask-matt/`）；路线中的每个技能在执行前都先读取其 `SKILL.md`（核实职责及 frontmatter 是否设有 `disable-model-invocation: true`），相对链接按该技能所在目录解析，所需参数结合上下文填入。
2. 缺少 `ask-matt` 或任一下游技能时停止，说明缺失的技能名与安装方式，不凭记忆执行。

## 路线图

1. 按当前需求的复杂度、清晰度与上下文状态，现场评估并抉择**适合的**单个技能或最小必要技能组合，不为凑齐主线而附加多余步骤（如目标清晰的单会话改动可直接选用 `/implement` 或 `/tdd`）。首次回复先给出路线图（序号、技能、推进方式［自动／门禁提示］、确需确认的待定分支），随即处理第一步，不单独等待对路线图的确认。
2. 需求不需要或不适合 matt 技能（如编辑 docx 标书、整理比价表或简单直接改动）时说明原因，只保留有用的技能，或建议不使用 matt 技能直接完成。
3. 仅当所选路线确有待定分支（如是否需要原型、走 `/implement-spec` 还是逐单 `/implement`）时，在对应门禁处一并确认。
4. 多工单并行优先选用会话内子代理（`/implement-spec`）；仅在必须清空上下文或隔离目录时拆分为新会话。

## 门禁与收尾输出

门禁处首行沿用[进度标识](stepping/workflow.md#进度标识)，然后依次写：

1. 当前位置：第 N 步 / 共 M 步，以及本步目标。
2. 用户要做的事：在本会话直接回答的问题，或可直接复制粘贴的代码块提示词。
3. 完成证据与停止条件：触发后将推进到哪一步、在哪里再次停下。

整条路线全部执行完毕时，首行写 `100%` 进度标识，给出完成证据与验收清单。

代码块中的技能命令按当前客户端显式调用写法书写：Claude Code 与 Antigravity 为 `/<技能>`，Codex 为 `$<技能>`。

# 多工单编排与极简提示词

适用于 `letsgo:matt-flow` 与 `letsgo:try-swarm` 共用的多工单实施形态评估、编排器互斥择优与极简提示词规范。

## 1. 多工单实施三档择优

进入多工单实施前，先按任务分布、依赖关系与门禁需求现场三档择优；严禁建议同时手动开启多个互不通信的顶层会话去跑带阻塞依赖的任务链：

1. **单仓库标准任务图**（同仓 `/to-spec` + `/to-tickets` 产出、合入同一集成支）→ 选用 **1 个会话跑 `/implement-spec`**（Codex 为 `$implement-spec`），由其自带任务图依赖解锁与 worktree 并发推进，不叠加宿主原生多智能体。
2. **跨多仓库、含人工中途门禁、或需异构分工／共享协调板**（含跨仓串行依赖链）→ 选用 **1 个宿主原生多智能体协调会话**（Antigravity `swarm`、Claude Code `Agent Teams`、Codex `multi_agent_v2`）：由薄协调者读取任务与依赖图，按依赖拓扑派发隔离上下文的 worker 逐单执行单任务粒度能力（如 `/implement`、`/tdd`）；无写冲突的跨仓或独立面可并行，有阻塞依赖等上游验收完再解锁下游，仅在确需人工审批的门禁处汇报停下。
3. **独立小单（1～2 单）或强需用户逐单深度审阅／跨宿主切换** → 拆分为逐单独立新会话（无阻塞依赖的工单标明可同时并行开启）。

## 2. 编排器互斥与择优选一

宿主原生多智能体与同类多代理／任务图编排器（如 `implement-spec`、`run_workflow` 或其他自带多代理调度的技能）**绝不同时叠加启用**。检测到当前消息或上下文中同时指定时，按第 1 节准则现场择优选一，并在报告末尾附一句避坑提醒：`（两者同属编排器，下次择一即可）`：

- **选原生多智能体替代对方编排器**：按宿主原生机制推进，并明令各 worker 只调用单任务粒度能力（如 `/implement`、`/tdd`），禁止在 worker 内再次调用被替代的编排器。
- **选对方编排器放弃原生多智能体**：若用户已在当前消息或上下文中明确指名该编排器，输出决策与避坑提醒后直接按当前任务节奏以该编排器推进；仅当受宿主显式调用限制无法直跑时，停下给出对应的 1 行极简原生代码块提示词。

## 3. 极简提示词与三端原生写法

- **最小上下文指针原则**：新会话或门禁代码块提示词力求极简（通常 1 行），便于用户看几次后脱离插件手写。凡工单、spec、handoff 或仓库 `AGENTS.md` 中已写明的目录、分支、步骤与完成标志，一律不再抄进代码块；仅在文档未写明时追加一句必要约束（如 `；部署前停下`）。
- **元信息外置**：依赖顺序、涉及仓库、是否可并行与人工门禁提醒等，写在代码块外用极简短语标注。
- **三端原生极简写法**（按当前宿主自动输出，进入明确单一实施形态时不前置 `letsgo:matt-flow` 或 `letsgo:try-swarm`）：
  - **单单**：Claude Code 与 Antigravity 写 `/implement <工单>`；Codex 写 `$implement <工单>`。
  - **单仓整套 spec**：Claude Code 与 Antigravity 写 `/implement-spec <spec>`；Codex 写 `$implement-spec <spec>`。
  - **跨仓／多门禁原生多智能体**：
    - Antigravity：`/swarm 按依赖逐单 /implement <spec或工单范围>`
    - Claude Code：`用 Agent Teams 按依赖逐单 /implement <spec或工单范围>`
    - Codex：`用多代理按依赖逐单 $implement <spec或工单范围>`

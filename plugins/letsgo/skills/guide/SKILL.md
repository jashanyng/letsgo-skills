# letsgo: guide

遵守[语言约定](../letsgo/references/language.md)；其他规则按[letsgo 规则入口](../letsgo/SKILL.md)命中时读取。

按当前需求在**能力范围**内现场评估适合的**能力**（skill、MCP 与内置工具的统称），逐步推进达成目标并呈现用法要点。

## 1. 识别需求与能力范围

1. **需求**：未给出目标且上下文无可推断任务时，只问一句请用户补充需求。
2. **能力范围**（本次优先考虑的能力集合，按以下优先级锁定）：
   - 本次消息明确指定的范围（“全部能力”“全部”或“all”同义，均指当前宿主支持的全部能力）；
   - 上下文明确表达“用 X 来做”的指定（仅提及或讨论某能力不算指定）；
   - 默认取“全部能力”。
3. **基础与范围外能力**：读写文件、终端、搜索等基础内置能力始终可用；范围外已安装的 skill 或 MCP 明显更适合当前需求时直接采用，并在过程说明行加注`（范围外）`。

## 2. 两段低耗筛选

仅基于当前会话实时上下文筛选，同会话已评估结论直接复用，保持无状态而不创建持久化能力索引文件。

1. **初筛**：仅看会话已载入能力清单的名称与描述做内部筛选，回复中只输出选定结论，不罗列完整清单。
2. **深读**：仅对入围候选读取 `SKILL.md` 或 MCP Schema 核实细节，单轮一般不超过 3 个；确需更多时简短说明原因。
3. **未生效处理**：指定范围内某能力在当前宿主未生效（未安装或未启用）时，提示未生效并转入下方“缺少必要支持”处理，以实读定义为准，不凭记忆执行。

## 3. 执行节奏与提示词

按筛选结果对应以下情形推进：

- **可隐式触发或直接调用的能力**（未设 `disable-model-invocation: true` 的 skill、MCP 或内置工具）：直接推进，每采用一项输出一行：
  - 范围内：`【guide】采用 <能力> —— <一句话用途>`
  - 范围外：`【guide】采用 <能力>（范围外）—— <一句话用途>`
- **必须显式调用的技能**（设了 `disable-model-invocation: true`）：
  - **默认停下**：给出以目标原生命令开头的代码块提示词后等待用户发送（同会话多轮需用户接力时同此）；Claude Code 与 Antigravity 写 `/<skill>`，Codex 写 `$<skill>`，必要时附一句话上下文，同会话继续时不前置 `letsgo:guide`。
  - **调用时明确授权代跑**：仅当用户在调用时明确授权（如“显式技能可代为执行”），才在本会话内读取其 `SKILL.md` 直接执行并输出上述 `【guide】采用 ...` 说明行；涉及发布、推送、删除或覆盖等操作仍遵守[变更安全](../letsgo/references/change-safety.md)等规则。
- **无匹配扩展能力但当前客户端可直接实施**：输出一行 `【guide】无匹配能力，直接实施 —— <原因>`；是否停下由当前现场需求决定，`guide` 不干预。
- **缺少必要支持**：当前能力均不足以完成目标或指定能力未生效且无可靠替代时，优先检索宿主自带市场（Antigravity 使用 `search_marketplace`，Claude Code 与 Codex 查询插件市场），已安装 `find-skills` 时配合使用，必要时联网检索；只报告、不安装——列明名称、用途、安装方式及不添加时的替代做法，停下等待用户决定。

## 4. 收尾

全部任务完成后，输出一段简短总结，列出本次使用的各项能力与各自用法要点。

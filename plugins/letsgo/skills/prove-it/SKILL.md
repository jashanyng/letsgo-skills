# letsgo: prove it

遵守[语言约定](../letsgo/references/language.md)；其他规则按[letsgo 规则入口](../letsgo/SKILL.md)命中时读取。

对当前改动或新增功能现场评估适合的测试验收层度与方法，给出三个选项供用户选择后实施。

## 确定目标

1. 调用消息指定了项目或改动范围时，评估该范围。
2. 未指定时，从当前对话上下文和工作区 `git diff`/`git status` 推断待验证的改动；无可推断时询问用户。

## 评估维度

综合以下维度现场评估：

- 改动范围与影响面（文件数、模块跨度、公共接口变动）
- 改动风险（破坏性变更、安全敏感、数据迁移）
- 项目已有的测试基础设施（已有测试框架、CI 配置、现存测试覆盖率）
- 平台与技术栈特性（前端/后端/移动端/CLI/插件/基础设施各有适合的验证手段）

## 测试层度参考

从轻到重：静态检查 → 单元测试 → 组件或快照测试 → 集成测试 → 端到端自动化 → 真实环境手动验收 → 预发或内测 → 灰度上线加监控。根据平台特性可调整或替换。

## 输出三个选项

| 选项 | 含义 |
| --- | --- |
| **A. 推荐** | 现场评估认为投入产出比最优的测试组合 |
| **B. 轻量** | 比推荐精简一档，快速验证核心路径 |
| **C. 深度** | 比推荐加一档，更高置信度 |

每个选项列出具体的测试层度组合与简要说明。

## 实施

用户选择选项后立即实施（不二次确认），完毕后输出验收报告：通过项、失败项、覆盖范围与建议。

# letsgo: git wrap

遵守[语言约定](../letsgo/references/language.md)与[变更安全](../letsgo/references/change-safety.md)；其他规则按[letsgo 规则入口](../letsgo/SKILL.md)命中时读取。

对任务涉及的所有 Git 仓库执行终局收尾：完成安全检查与英文提交，安全合并并推送至源分支，评估并清理已合入的工作树与临时分支。

## 1. 确定目标仓库与改动范围

- **有前序任务上下文时**：
  - 纳入本次会话修改过、创建过工作树或用户点名的所有 Git 仓库（含子仓库与关联的链接工作树）。
  - 只暂存并提交本次任务相关的改动，保留任务前无关改动及其原有暂存状态；若无关脏改动与本次改动混杂且无法安全剥离，停下询问用户。
- **空白会话直接调用（或附带路径说明）时**：
  - 纳入用户指定路径或当前工作目录所在仓库。
  - 若当前目录为多仓库父目录，一并扫描其下存在未提交改动、未推送提交或关联链接工作树的全部子仓库，将当前未提交改动视为待收尾内容。
- **无需操作判定**：工作区干净、无未推送提交且无待合并或待清理的工作树／任务临时分支的仓库，直接记为“无需操作”。

## 2. 安全检查与英文提交

- **提交前逐仓检查**：逐仓检查 `git status` 与差异（含工作区及已暂存内容）；若拟提交内容疑似含密码、令牌、私钥等秘密，或混入不应入库的大型构建产物／临时垃圾文件，停止该仓操作并报告用户。
- **英文提交**：有待提交改动时，紧扣任务目标与实际修改内容撰写简洁准确的英文提交信息（沿用仓库既有英文前缀或 Conventional Commits 惯例，标题与正文均用英文）完成本地提交。无新改动但存在既往未推送提交或待合并任务分支的仓库，跳过本步进入后续检查。

## 3. 甄别分支角色与源分支

- **长期分支刚性保护**：`main`、`master`、`dev`、`develop`、`trunk`、`staging`、`production` 及 `release/*` 永远视为源分支本身——当前位于这些分支时只做原地提交与推送，严禁将其当作任务分支合并到其他分支，也严禁删除。
- **非保护分支甄别**：
  - 仅当处于链接工作树（linked worktree），或有明确证据表明当前分支为任务自动新建的临时分支（如本会话新建、`claude/*`、`codex/*`、`worktree-*` 等单任务临时分支且分叉源可考）时，才执行向源分支回并。
  - 若属于需保留的 `prototype/*` 原型分支，或无法断定是否为临时分支，停下请用户确认（由用户决定原地推送当前分支或合并至指定源分支），不擅自回并。
- **源分支推断优先级**（用户未指定时按序判定）：
  1. 本次会话创建该分支／工作树时的起点分支，或 `git reflog` 分支创建记录；
  2. 链接工作树对应的主检出目录（由 `git worktree list --porcelain` 定位）当前检出的长期分支，并经 `git merge-base` 核验分叉拓扑；
  3. 与当前分支分叉拓扑最近的长期分支（分叉距离相同时优先 `dev`／`develop`，其次 `main`／`master`）。
- **歧义即停**：一旦存在歧义（例如同时存在活跃的 `dev` 与 `main` 且无法从分叉点或主目录状态可靠区分，或找不到可靠的分叉源），立即停下请用户提供源分支信息，绝不盲猜。

## 4. 合并与推送

- **原地源分支（或确认不回并的常规分支）**：推送到远程跟踪分支（无跟踪分支时推送同名远程分支并建立跟踪；仓库未配置任何远程时仅保留本地提交并说明）。
- **工作树或任务临时分支**：
  - 若源分支已在主检出目录被检出：先确认主检出目录无冲突脏改动（有阻碍合并的无关未提交改动时停下报告，不覆盖既有工作区内容），再通过主检出目录（`git -C <主检出目录>`）将任务分支合并进源分支并推送源分支。
  - 若源分支未被其他工作树检出：在主检出目录或当前目录切换至源分支合并并推送（若源分支已在其他非主工作树检出，先核查该工作树是否干净并避免状态冲突）。
- **停止保护**：遇到合并冲突（先用 `git merge --abort` 中止未完成的冲突合并以保留干净现场）、远程分支受保护要求 PR 或推送被拒时，保留现场停下报告，严禁 `--force` 强制推送。推送触发 CI 时不等待轮询，在报告中注明。

## 5. 清理评估与收尾报告

- **四项安全门槛**：对已完成源分支合并与推送的工作树／任务临时分支，按以下门槛评估是否推荐清理：
  1. 任务提交已完整合入源分支，且源分支已成功推送到远程（仅无远程时以本地源分支合并完成为准）；
  2. 待删工作树内无未提交变更或未跟踪残留文件；
  3. 待删分支不在长期保护名单、非 `prototype/*` 原型分支且无未关闭的关联 PR；
  4. 当前工作目录若位于待删工作树内，已先切换回主检出目录。
- **清理决策与执行**：
  - 四项全部满足时判定为“推荐删除”，直接执行 `git worktree remove` 移除链接工作树，并删除已合并的本地临时任务分支（若本轮曾推送过同名远程临时分支且无 PR，一并删除远程临时分支）；
  - 任一项不满足时判定为“不推荐删除”，保留工作树／分支并说明具体原因。
- **收尾报告**：按仓库逐项输出汇总报告，涵盖：
  - 仓库路径；
  - 分支动作（原地推送／合并入哪个源分支／无需操作）；
  - 英文提交哈希与摘要；
  - 远程推送结果（含是否触发 CI 的注明）；
  - 工作树与临时分支的清理评估及执行状态（或停下待用户决定的事项）。
